# OneShot API — current candidate routes

Single-operator; local server by default. CLI uses `Authorization: Bearer <server-provided token>` on all `/api/*` paths. Browser uses a same-origin login session, NOT an API bearer token.

## Browser authentication

- `POST /auth/login` with JSON `{ "password": "..." }`. When configured server-side, returns `authenticated` and a CSRF nonce, and issues an HttpOnly SameSite=Strict cookie. Rate-limits failed attempts.
- `GET /auth/session` checks cookie validity and returns CSRF nonce for this session; unauthenticated requests receive 401.
- `POST /auth/logout` requires cookie and `X-Oneshot-CSRF`; revokes session and expires cookie.
- Browser session requests to mutating `/api/*` endpoints require `X-Oneshot-CSRF`, and cross-origin requests are refused; explicit bearer requests remain supported for CLI.
- Cookies are marked Secure for HTTPS connections. Configure the actual trusted HTTPS deployment and proxy before exposing remotely. In-memory browser sessions are single-process, not multi-host.

## System API

- `GET /health`, `GET /api/capabilities`
- `POST /api/conversations`, `GET /api/conversations/{cid}`
- `PATCH /api/conversations/{cid}/session`, `POST /api/conversations/{cid}/messages`, `POST /api/conversations/{cid}/agent/replies` (only for configured optional Agents)
- `POST /api/conversations/{cid}/sources/actions`, `GET /api/conversations/{cid}/sources`, `GET /api/conversations/{cid}/sources/available`, `GET /api/conversations/{cid}/sources/{sid}/content`
- `POST /api/conversations/{cid}/jobs`, `GET /api/conversations/{cid}/jobs/{jid}`, `GET /api/conversations/{cid}/runs/{rid}`
- `GET /api/conversations/{cid}/events`, `GET /api/conversations/{cid}/events/stream` (SSE), `GET /api/conversations/{cid}/jobs/{jid}/trace`
- `GET /api/conversations/{cid}/artifacts/{aid}`, `GET /api/conversations/{cid}/artifacts/{aid}/evidence`, `GET /api/conversations/{cid}/artifacts/{aid}/evidence/{sid}/content`, `GET /api/conversations/{cid}/artifacts/{aid}/export`, `GET /api/conversations/{cid}/artifacts/{aid}/summary` (strict summary-only `output.json`)
- `POST /api/conversations/{cid}/drafts`, `PATCH /api/conversations/{cid}/drafts/{did}`, `GET /api/conversations/{cid}/drafts/{did}`
- `POST /api/conversations/{cid}/apply/prepare`, `POST /api/conversations/{cid}/apply/confirm`, `GET /api/conversations/{cid}/apply/target`, `GET /api/conversations/{cid}/applied/{id}`

System supports deterministic evidence preparation by default. Unconfigured image/PDF viewing and research retrieval are not performed. Agent replies are available only when explicitly configured server-side. Agent activation without a configured provider returns 409; the primary System remains available. Activated Agent sessions make System mutation endpoints read-only until deactivation; Agent cannot invoke source tools or Apply.

`frontend/dist/` is generated by `npm run build`, then mounted at `/`. Without the build FastAPI returns 503 for the index page. No invented provider installation endpoints are included.

## Grounded System Job admission

`POST /api/conversations/{cid}/jobs` requires an existing, nonempty **System** message
within the same conversation. The browser shows the newest saved System message
as the objective before Start and refuses to start with an unsent composer draft.

```json
{
  "operation": "auto_generate",
  "prompt_message_id": "<id of persisted System message>",
  "source_ids": ["<selected source id>"],
  "expected_versions": {"<selected source id>": 1},
  "idempotency_key": "unique-client-request-key"
}
```

The Job persists the `prompt_message_id`; replay with the same key but a different
prompt or selected scope returns 409. Missing, mismatched-conversation, or unknown
prompt IDs fail with 422. A v1 SQLite database is upgraded to schema v2 without
replacing existing data. Legacy queued jobs without a prompt fail closed.

The default artifact is **not a semantic answer**. It includes the requested
objective, source IDs/versions/hashes, numbered source lines, and optional literal
backtick-quoted code-term pointers (not semantic relevance). Model generation
remains explicitly configured and is not a substitute for factual verification.

## Optional configured model providers

System `ONESHOT_PROVIDER` accepts `evidence`, legacy `model` (OpenAI-compatible wire shape), `openai`, native `gemini`, and loopback `ollama`. Model requests use server-side secrets and bounded responses with strict `GeneratedDocument` validation. Agent integrations are separately server-configured. `GET /api/capabilities` returns only provider labels/model IDs, never secret values. `POST /api/conversations/{cid}/agent/replies` requires an active Agent session and JSON `provider`, `content`, `idempotency_key`; an accepted reply persists the user and assistant messages atomically. A provider failure persists neither. Client-supplied source IDs are never accepted on this Agent route. Read the full limitation and deployment gates in `docs/MODEL_INTEGRATIONS.md`.

## Implemented operation-specific dispatch and result kinds

The `JobCreate.operation` discriminator allows `inspect_sources`, `auto_generate`,
and `summarize`. Source Management operations remain separate from Job admission;
imports and scope changes do not trigger model work.

- `inspect_sources`: local source inspection without a model, with explicit
  incomplete/unusable coverage where applicable. Retains an evidence artifact.
- `auto_generate`: evidence packet in evidence mode; configured model output
  must meet its existing typed result contract.
- `summarize`: requires a configured provider. Output is persisted as kind
  `summary` only after strict Pydantic validation; export returns exactly
  `{"summary": "..."}` under `output.json`. No evidence packet is renamed.

The backend's Source Management now exposes the retained source library, while
Apply review confirms target baseline and returns read-back verified final
output. Actual security, model accuracy, browser and deployment validation
are separate required gates.
